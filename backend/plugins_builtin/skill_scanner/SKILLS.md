# 技能定义安全扫描（Skill Scanner）

## 这是什么

对 AI Agent 的工具/技能定义进行安全审计的插件。当 AI 应用使用 function calling（工具调用）时，攻击者可能通过恶意的工具定义注入提示、隐藏危险能力、或构造跨工具攻击链。这个插件在工具定义被发送给 LLM 之前，对其进行全面扫描。

## 核心能力

### 静态模式检测

35+ 正则模式，分四组检测：

- 提示注入：工具描述中嵌入的指令注入、系统提示覆盖、角色分配、越狱触发词
- 命令注入：eval/exec/system 等代码执行函数、shell 命令、危险导入
- 数据泄露：外部数据传输指令、敏感凭证引用、回调 URL
- 混淆手法：base64/hex 编码、Unicode 转义链、加密函数调用

### 结构验证

检查工具定义的 JSON Schema 是否安全合规：

- Schema 合规性：是否有合法的 name、description、parameters
- 参数约束：敏感参数名（command、query、code、script）是否缺少 enum/pattern/maxLength 约束
- 描述质量：描述缺失、过短（< 10 字符）、过长（> 1000 字符，可能藏匿恶意内容）
- 工具名安全：是否匹配 execute_shell、run_command、eval_code 等危险模式

### 能力风险分析

对工具的实际能力进行分类和风险评估：

- 8 类能力识别：文件系统、网络、代码执行、数据库、认证、系统管理、邮件、浏览器
- 单工具风险：代码执行 + 系统管理能力组合 → 高风险
- 跨工具攻击链检测（核心差异化能力）：
  - 文件/数据库 + 网络 → 数据泄露链
  - 代码执行 + 网络 → 远程代码执行
  - 认证 + 代码执行 → 权限提升
  - 文件系统 + 代码执行 → 持久化威胁
  - 数据库 + 代码执行 → SQL 注入到代码执行

### LLM 语义分析（可选）

当 Phase 1 检测到中等以上风险时，可自动触发 LLM 进行深度语义分析，并过滤 Phase 1 的误报。

## 适用场景

以下场景强烈推荐启用：

- AI Agent 应用：使用 function calling 的智能体，尤其是工具数量 > 5 个的复杂 Agent
- 第三方工具接入：接入外部 MCP Server、插件市场、第三方 API 工具包的场景，需要审计工具定义安全性
- 多工具协作场景：Agent 同时具有文件操作、网络访问、代码执行等多类能力时，跨工具攻击链风险显著升高
- 工具定义动态变化：工具定义来自用户输入或外部配置，而非硬编码，存在注入风险

## 不适用场景

- 纯对话应用：没有使用 function calling / tool use 的聊天机器人不需要此插件
- 固定少量工具：只有 1-2 个内部硬编码的简单工具，且工具定义不接受外部输入

## 性能特征

- Phase 1（3 引擎并行）：< 50ms，不依赖 GPU
- Phase 2（LLM 语义）：500-2000ms，仅在检测到中等以上风险时触发
- 支持单次请求最多 100 个工具定义

## 与其他插件的关系

- 依赖基础安全防护作为基础
- 与 Agent 安全防护高度互补：Skill Scanner 扫描工具定义（部署前/请求时），Agent Safety 监控工具实际调用（运行时）。建议同时启用
- 与幻觉检测无直接关联
