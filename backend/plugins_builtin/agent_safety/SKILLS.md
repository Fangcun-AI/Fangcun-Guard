# Agent 安全防护（Agent Safety）

## 这是什么

为 AI Agent 的运行时行为提供全方位安全监控的插件。当 AI Agent 实际调用工具、生成参数、进行推理时，这个插件实时检测注入攻击、异常行为和对齐偏离。与技能定义安全扫描（Skill Scanner）的区别在于：Skill Scanner 审计的是工具"长什么样"，Agent Safety 监控的是工具"怎么用"。

## 核心能力

### 工具调用白名单/黑名单

控制 Agent 可以使用哪些工具：

- 白名单模式：仅允许指定工具被调用，其他一律拦截
- 黑名单模式：禁止特定危险工具被调用
- 支持通配符匹配，灵活配置

### 工具参数注入检测

11 种内置正则模式，实时检测 Agent 生成的工具调用参数中的注入攻击：

- Shell 命令注入：参数中包含 `; rm -rf`、`$(cmd)`、反引号执行等
- 路径遍历：`../../etc/passwd` 等目录遍历攻击
- SQL 注入：`' OR 1=1 --` 等 SQL 注入模式
- SSRF：参数中指向内网地址（127.0.0.1、10.x.x.x、metadata 服务）
- 代码注入：`eval()`、`exec()`、`__import__()` 等
- 环境变量窃取：`$ENV`、`process.env`、`os.environ` 等

这是防御 Agent 被提示注入后"做坏事"的最后一道防线。

### 推理链安全审计（CoT Audit）

检测 Agent 的思维链（Chain-of-Thought）中是否出现安全问题：

- 目标劫持：推理链中出现与用户请求无关的隐藏目标
- 注入影响：推理链显示 Agent 受到注入攻击的影响
- 对齐偏离：Agent 的推理过程偏离预设的安全准则
- 数据窃取意图：推理链中出现收集或外传敏感数据的计划

推理链审计需要模型支持 reasoning/thinking 输出（如 OpenAI o1/o3、Claude 的 extended thinking），是目前业界最前沿的 Agent 安全技术之一。

## 适用场景

以下场景强烈推荐启用：

- AI Agent 应用：任何使用 function calling 并实际执行工具调用的 Agent 系统
- 高权限 Agent：Agent 具有文件操作、数据库访问、API 调用、代码执行等敏感权限
- 面向用户的 Agent：Agent 直接接受终端用户输入，存在提示注入风险
- 推理模型场景：使用 o1/o3/Claude thinking 等支持推理链输出的模型，可以开启 CoT 审计获得更深层的安全保障
- 自主决策 Agent：Agent 有较大自主权，需要监控其决策过程是否安全

## 不适用场景

- 纯对话应用：没有工具调用的聊天机器人不需要此插件
- 只读工具 Agent：Agent 只使用查询类工具（如搜索、天气查询），不涉及写操作或敏感操作
- 无推理链的模型：如果不使用支持 reasoning 输出的模型，CoT 审计功能将不会触发（但工具调用检测仍然有效）

## 性能特征

- 工具白名单/黑名单检查：< 1ms
- 参数注入检测：< 5ms（11 条正则匹配）
- 推理链审计：100-500ms（需要调用检测模型）
- 仅在白盒模式（安全网关 5002 端口）下工作

## 与其他插件的关系

- 依赖基础安全防护作为基础
- 与技能定义安全扫描（Skill Scanner）是最佳搭档：Skill Scanner 在请求发送前审计工具定义是否安全，Agent Safety 在运行时监控工具实际调用是否异常。两者覆盖 Agent 安全的不同阶段，强烈建议同时启用
- 与幻觉检测可以互补：Agent 执行复杂任务时，幻觉检测可以验证 Agent 的输出是否基于事实
