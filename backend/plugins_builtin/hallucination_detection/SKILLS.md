# 幻觉检测（Hallucination Detection）

## 这是什么

对 LLM 输出进行事实依据和内部一致性双维度检测的插件。LLM 可能生成看似合理但完全错误的内容（幻觉），在企业应用中这会导致错误决策、合规风险和用户信任损失。这个插件通过对比输出与参考上下文，评估每条输出的可信度。

## 核心能力

### 事实依据检测（Groundedness）

评估 LLM 的输出是否有据可依：

- 将 LLM 输出与提供的参考上下文（如 RAG 检索结果、系统提示中的知识、用户提供的文档）进行对比
- 返回 0.0 到 1.0 的评分，表示输出内容被参考材料支持的程度
- 低于阈值的输出会被标记为潜在幻觉

上下文来源支持多种方式：
- System Message 中的参考内容（RAG 场景最常见）
- API 参数 extra_body.context（显式传入参考文本）
- API 参数 extra_body.documents（传入文档列表）

### 内部一致性检测（Consistency）

检查 LLM 输出内部是否自相矛盾：

- 分析输出中的不同声明之间是否逻辑一致
- 例如：前文说"该产品 2023 年发布"，后文又说"已有 5 年历史"（当前 2026 年）
- 返回 0.0 到 1.0 的评分

### 可配置阈值

- groundedness_threshold：默认 0.6，低于此分数判定为幻觉
- consistency_threshold：默认 0.7，低于此分数判定为不一致
- 可根据应用场景调整灵敏度：对准确性要求高的场景（如医疗、法律）建议调高阈值

## 适用场景

以下场景强烈推荐启用：

- RAG 应用（检索增强生成）：这是幻觉检测价值最大的场景。LLM 基于检索到的文档生成回答，幻觉检测验证回答是否忠实于检索结果，防止 LLM "自由发挥"
- 知识问答系统：基于企业知识库的问答，需要确保回答准确无误
- 文档摘要和分析：LLM 对文档进行摘要或分析时，需要确保输出忠实于原文
- 医疗、法律、金融咨询：对准确性要求极高的专业领域，幻觉可能导致严重后果
- 报告生成：自动生成的报告需要数据和结论一致

## 不适用场景

- 创意写作：故事创作、诗歌生成等场景中，"幻觉"反而是创造力
- 无参考上下文的开放对话：如果没有提供参考材料，事实依据检测无法评估（但一致性检测仍然有效）
- 纯指令执行场景：用户要求"翻译这段话"、"格式化这段代码"等不涉及知识生成的任务
- 实时聊天中的闲聊：日常对话不需要严格的事实验证

## 性能特征

- 事实依据检测：200-800ms（需要调用检测模型进行语义比对）
- 一致性检测：200-800ms（需要分析输出内部逻辑）
- 两项检测可独立开关，按需启用
- 支持黑盒 + 白盒两种部署模式

## 与其他插件的关系

- 依赖基础安全防护作为基础
- 与 Agent 安全防护互补：Agent 执行任务后，幻觉检测可以验证 Agent 生成的报告或回答是否可信
- 与技能定义安全扫描无直接关联（扫描工具定义不涉及幻觉问题）
- 在 RAG 场景中价值最高，如果应用不涉及基于上下文的知识生成，优先级可以降低
