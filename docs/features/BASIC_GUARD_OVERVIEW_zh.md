# Fangcun Core Shield 概述

## 1. 项目背景

随着大语言模型在各行业的广泛应用，AI 系统面临的内容安全风险越来越多。这些风险包括：

- 用户通过提示攻击（Prompt Injection）试图绕过安全限制
- 提示攻击成功后，LLM 在输出中泄露系统提示词或内部指令
- 模型生成暴力、色情、仇恨等有害内容
- 用户输入或模型输出中包含身份证号、信用卡号等敏感信息（数据泄露）
- 流式输出场景中，恶意内容在逐 token 传输过程中无法被实时检测
- 恶意用户反复发起高风险请求，消耗系统资源

Fangcun Core Shield 是 Fangcun Guard 的安全基座插件，提供从内容安全检测、数据泄露防护到流式输出审计的全方位基础防护能力。它是其他所有安全插件的前置层，所有请求都会先经过 Fangcun Core Shield 的检测。

## 2. 技术现状

Fangcun Core Shield 的能力分为两部分：**核心检测系统**（运行在 Fangcun Guard 主服务中）和 **流式输出安全检测**（运行在 `basic_guard` 插件 Hook 中）。

### 2.1 核心检测系统

核心检测系统由 Fangcun Guard 主服务提供，包含以下五项能力：

- **内容安全检测**：基于安全模型对输入和输出文本进行 21 类风险分类（S1-S21），支持 119 种语言。风险按严重程度分为三级处置：
  - 高风险（自动拦截）：敏感政治话题（S2）、侮辱国家象征（S3）、暴力犯罪（S5）、提示攻击（S9）、大规模杀伤性武器（S15）、性犯罪（S17），共 6 类。
  - 中风险（可配置）：未成年人伤害（S4）、非暴力犯罪（S6）、色情内容（S7）、自残自杀（S16），共 4 类。
  - 低风险（默认放行）：一般政治话题（S1）、仇恨歧视（S8）、脏话（S10）、隐私侵犯（S11）、商业违规（S12）、知识产权侵犯（S13）、骚扰（S14）、威胁（S18）、专业金融建议（S19）、专业医疗建议（S20）、专业法律建议（S21），共 11 类。
  - 对于超长文本，采用滑动窗口检测（默认窗口 7168 token，20% 重叠），所有窗口并行执行，任一窗口触发即判定匹配。

- **数据泄露防护（DLP）**：自动识别身份证号、信用卡号、手机号、邮箱等敏感实体。支持两种识别方式：正则匹配（适用于格式化数据）和 GenAI 实体识别（适用于自然语言中的敏感信息）。系统能自动识别输入文本的格式（JSON、YAML、CSV、Markdown），按格式结构智能分段（每段不超过 4000 字符），避免在拆分时破坏数据结构。提供五种处置策略：
  - 阻断（block）：直接拦截请求。
  - 脱敏（anonymize）：将敏感信息替换为占位符（如 `张三` → `[PERSON]`）。
  - 可逆脱敏（anonymize_restore）：用编号占位符替换（如 `张三` → `[PERSON_1]`），在输出时自动还原。
  - 切换私有模型（switch_private_model）：将请求自动转发到企业私有模型处理。
  - 仅记录（pass）：不干预，仅记录审计日志。

- **黑名单/白名单**：基于关键词的快速过滤。白名单命中即放行（跳过后续所有检测），黑名单命中即拦截。运行在内存缓存中，延迟低于 1 毫秒。

- **封禁策略**：当某个用户或 IP 在指定时间窗口内多次触发高风险检测时，自动封禁。触发阈值、时间窗口和封禁时长均可配置。

- **响应模板/知识库**：为拦截场景提供定制化的安全引导响应。知识库支持基于 FAISS 的向量相似度匹配，根据用户输入内容返回最相关的安全引导话术。

### 2.2 流式输出安全检测

流式输出检测由 basic_guard 插件提供，通过 Hook 机制在流式传输完成后对完整输出进行安全审计。包含三个并行检测引擎：

- **内容模式引擎**：使用 4 条正则表达式检测输出中的安全异常，包括系统提示词泄露（"my system prompt is" 等）、越狱模式激活（"DAN enabled" 等）、指令覆盖确认（"ignoring previous instructions" 等）、编码混淆输出（base64/hex/rot13 后跟大量字符）。

- **推理偏离引擎**：使用 3 条正则表达式检测模型推理链（CoT）中的异常偏离，包括意图重解读（"the user actually wants" 等）、安全绕过推理（"I should ignore" 等）、角色扮演偏离（"pretend"、"act as if" 等）。

- **输出异常引擎**：使用 50 字符滑动窗口检测输出中的重复循环模式。当重复率超过阈值（默认 40%）时标记为异常。

三个引擎并行执行，总检测延迟低于 5 毫秒。
