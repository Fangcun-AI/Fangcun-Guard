# MCP Scanner 概述

## 1. 项目背景

MCP（Model Context Protocol）正在成为 AI Agent 连接外部工具和数据源的标准协议。与传统的 function calling 不同，MCP 服务器除了工具（tools）定义之外，还暴露了提示词模板（prompts）、资源（resources）和服务器初始化指令（instructions）等协议特有构件。这些构件带来了新的安全威胁：

- 工具投毒（Tool Poisoning）：在工具描述中嵌入隐蔽的行为操纵指令，如工具影子化（让 Agent 优先使用恶意工具替代合法工具）、隐蔽操作（在正常功能背后执行未声明的操作）。
- 提示词模板注入：通过 prompts/list 返回的模板中嵌入系统提示覆盖、上下文污染、特权变量注入。
- 资源 URI 攻击：利用 resources/list 返回的资源 URI 进行 SSRF（如 file:///etc/passwd）、云元数据访问（169.254.169.254）、可执行 data: URI 等攻击。
- 服务器指令操纵：在 MCP 服务器初始化指令中隐藏权限提升、安全检查绕过、自动批准等恶意行为。
- 跨服务器攻击链：多个 MCP 服务器的能力组合可能形成攻击链，例如 Server A 提供文件读取能力 + Server B 提供网络发送能力 = 数据泄露链。

MCP Scanner 对 MCP 服务器进行部署前安全审计，专注于 MCP 协议独有的安全威胁，与 Skill Scanner（扫描 SKILL.md 工具定义）和 Agent Safety（运行时工具调用监控）互补不重叠。

## 2. 技术现状

MCP Scanner 采用两阶段扫描架构，包含三个检测引擎，共覆盖 22 种威胁类别。

### 2.1 第一阶段：YARA 规则引擎 + 跨服务器分析

第一阶段由两个引擎并行执行：

- **YARA 规则引擎**：使用 29 条预编译正则表达式对 MCP 服务器的四个维度进行模式匹配，按扫描对象分为六组：
  - 工具投毒规则（5 条）：检测工具描述中的行为操纵、工具影子化、隐蔽操作、用户欺骗、数据收集等 MCP 特有的投毒模式。
  - 提示词模板规则（5 条）：检测 prompts 模板中的系统提示覆盖、上下文污染、特权模板变量、代码执行注入。
  - 资源 URI 规则（9 条）：检测 resources 中的敏感文件路径（/etc/passwd、.ssh/id_rsa 等）、SSRF 端点（云元数据地址）、可执行 data: URI、通配符路径、服务器端请求、凭证泄露等。
  - 资源内容规则（2 条）：检测资源内容中的敏感数据模式。
  - 服务器指令规则（7 条）：检测 instructions 中的权限提升指令、安全检查绕过、工具自动批准、数据外传指令、系统修改指令、隐蔽行为指令、用户交互操纵。
  - 混淆规则（1 条）：检测零宽字符等编码混淆手法，应用于所有维度。
  - 整体检测延迟低于 50 毫秒。

- **跨服务器信任边界分析引擎**：仅在同时扫描 2 个以上 MCP 服务器时触发。将每个服务器的工具按 8 种能力域（文件系统、网络、代码执行、数据库、认证、系统管理、邮件、浏览器）进行分类，然后检测跨服务器的 6 种攻击链：
  - 跨服务器数据泄露：文件系统 + 网络（critical）
  - 跨服务器远程代码执行：代码执行 + 网络（critical）
  - 跨服务器权限提升：认证 + 代码执行（critical）
  - 跨服务器数据库泄露：数据库 + 网络（high）
  - 跨服务器持久化：文件系统 + 代码执行（high）
  - 跨服务器横向移动：系统管理 + 网络（high）
  - 当所有服务器合计暴露 5 个以上能力类别时，额外发出聚合攻击面告警。
  - 整体检测延迟低于 100 毫秒。

### 2.2 第二阶段：LLM 语义分析

当第一阶段检测到中等以上风险时，LLM 语义引擎被条件触发。LLM 引擎可以识别正则规则无法覆盖的隐性风险，例如通过自然语言包装的工具投毒、语义级的权限提升暗示、隐蔽的数据外传意图等。同时，LLM 也会对第一阶段的检测结果进行误报过滤，提升整体精度。

### 2.3 扫描模式

MCP Scanner 提供三种扫描方式：
- 单次扫描：通过 POST API 提交一个或多个 MCP 服务器数据，最多支持 50 个服务器。
- 目录扫描（SSE）：指定本地目录路径，自动提取 MCP 配置文件（支持 Claude Desktop、LiteLLM、VS Code、E2B 四种格式），以 SSE 流式返回扫描进度和结果。
- Detection API：通过 FangcunGuard 的统一检测接口调用。

## 3. 项目方向

### 3.1 MCP 服务器运行时监控

当前 MCP Scanner 仅做部署前静态审计。但 MCP 服务器在运行过程中可能发生工具定义变异（Rug Pull）——即工具在初次审计时是安全的，但之后被动态修改为恶意版本。需要增加运行时监控能力，定期轮询 MCP 服务器的工具定义，与基线对比检测变更。

### 3.2 YARA 规则扩充

当前仅有 29 条 YARA 规则，覆盖面有限。特别是在工具投毒和提示词模板领域，攻击手法在快速演化。需要建立规则更新机制，持续跟踪 MCP 安全研究社区的新攻击手法，扩充检测规则库。

### 3.3 MCP 服务器代码级行为分析

当前的扫描完全基于 MCP 服务器暴露的元数据（工具描述、提示词模板等），不分析服务器的实际代码实现。参考 Cisco AI Defense 的做法，可以增加对 MCP 服务器源代码的静态分析能力，检测代码中隐藏的恶意行为（如暗中收集数据、执行未声明的系统命令等），这些行为无法通过元数据层面发现。
